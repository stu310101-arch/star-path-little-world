# 低配移動與轉鏡修正（2026-10-08）

切換低配／一般畫質現在保留玩家選定的 30／60／90 FPS 上限。低配仍調整 MSAA、植被與遠景，較大畫面才降低 3D 解析度；首次啟動及恢復預設仍採原本的低配／30 FPS，已保存的設定不被自動改寫。比較兩種畫質的實際成本時，應先將兩者設為相同幀率上限。

低配原本在 1280×800 的畫面使用 0.9 倍縮放，只少畫 19% 像素，卻增加中間緩衝的縮放／複製路徑。現在只在計算出的縮放比例 ≤ 0.8 時啟用縮放；較小視窗直接使用原解析度。這是避免收益有限的額外處理所採用的保守門檻，並非已量出所有 GPU 的效益分界。1920×1080 等大畫面保留原來的低解析度策略，該尺寸的效能改善未經本次測量。

角色的移動、碰撞、跳躍階段、行走時間與落地銜接時間仍由每次物理更新推進。骨架和布料姿態改為累積最新時間後，在角色每次 `_process` 套用一次，避免一個繪製幀前的多次物理更新重複立即取樣全部動畫軌道。落地時仍共同取樣跳躍與行走骨架；室內控制器繼承相同繪製流程。

`sample_motion_animation()` 也供停用自動處理的姿態檢查使用。物理逐步檢查會明確同步視覺姿態再量骨骼；獨立的 `animation_sampling_checks.gd` 檢查多步時間累積、姿態一致性與正常繪製更新節奏。原始 GLB、可編輯模型、動作資料及物理更新率未變更。

使用 `?performance` 時，`planetPerformance.animation` 提供累計 `physics_updates`、`pose_samples`、`seek_calls`。落地銜接的一次姿態套用可取樣兩套骨架，因此 `seek_calls` 可以高於 `pose_samples`；這些計數不是 GPU 執行時間。

## 驗證方法

修正前的本機 Web 產物保存在 `build/movement-before-20261008/`。`tools/check_movement_smoothing.cjs` 以實際滑鼠與鍵盤操作相同道路，交替測量兩種畫質，統一 60 FPS 上限及 MSAA 關閉。每個畫質各重複三輪站立、行走、轉鏡；保存真正提交 WebGL 畫面的幀間隔、P95／P99、超過 100 ms 的次數、區域載卸操作與下載狀態。

量測反映 CPU 提交畫面的節奏，不能代替 GPU 完成呈現的時間。背景負載、記憶體、溫度與 GPU 時脈未鎖定；必須一併查看每輪資料與串流工作標記，不能將平均 FPS 當成所有卡頓已修復。

## 功能檢查

- 畫質與設定保存：59 項通過，涵蓋兩種畫質在 30／60／90 FPS 下切換、重新讀取設定，以及縮放門檻兩側的尺寸。
- 動畫更新排程：28 項通過，6 次物理更新合併為一次姿態／一次 seek，行走時間仍累積完整 0.1 秒。稀疏取樣與每步取樣的最終骨架／形態權重差小於 `2.4e-7`，模型與骨架根節點變換一致。
- 跳躍物理：101 項通過，包括六方向球面、完整翻轉、落地回復、連跳限制與碰撞。
- 室內角色：11 項通過，包括移動、跳躍、落地、牆面碰撞與轉向。
- 室內座位互動：130 項通過，包括坐下、起身、座位姿態與起身後控制恢復。
- 嚴格全專案檢查：414 項、105 個場景實例化，零錯誤／警告。同步修正原有的局部名稱遮蔽、整數除法與不相容三元運算警告，未改變其數值／分支意圖。

上述均為 headless 功能驗證；不能代替實際渲染或瀏覽器效能結果。原始記錄保存在 `build/movement-fix/` 及 `deliverables/performance/animation-sampling-checks.json`。

原生 `check_jump_world.gd --capture-jump` 在進入遊戲前遇到 OpenGL／EGL／ANGLE 視窗初始化失敗，150 秒安全逾時後已停止該次程序。其錯誤記錄保存在 `build/movement-fix/jump-world-rendered.json`；不將該次執行列為遊戲動作或畫面驗證成功。

## 實際執行與量測限制

2026-10-08 的量測中途發生長時間執行環境暫停。`movement-after-20261008.json` 未產生任何測量區段，重試的 `movement-after-20261008-retry.json` 又遇到本機伺服器中斷，兩者均不作效能結論。恢復後以只提供匯出目錄的本機伺服器重新測試。

`movement-after-20261008-resumed.json` 保存新版六段實際量測，但下一輪操作設定選單時讀到尚未更新的 MSAA 狀態，等待條件逾時，未完成三輪。測試工具已改為不重按相同畫質，切換後等待該預設的 MSAA 狀態，再明確等待 MSAA 關閉及 60 FPS。遊戲設定邏輯未因測試逾時而修改。

此檔另保留兩筆原始「持續行走」判斷失敗。檢視位置與時間戳後，低幀率下的遙測快取及輸入起始延遲造成重複位置，後續兩段皆確實移動；另存的 `motion_review` 記錄此判讀，不刪除原始錯誤，也不將起始延遲當成穩定移動。

相同時段的舊版 `movement-before-20261008-resumed.json` 完成三輪、九段測試且無錯誤。舊版低配行走為 4.25／4.27／3.88 FPS，P95 為 298.6／311.5／335.9 ms；新版已完成的一輪低配行走為 4.13 FPS、P95 280.0 ms。所有這些行走區段均無區域載卸操作。這不足以宣稱動畫排程修正提高行走 FPS，也不能拿恢復前約 14.66 FPS 的舊資料與恢復後資料計算改善幅度。

新版本機遙測已確認低配行走的 190 次物理更新合併為 15 次姿態／seek；一般畫質的 129 次合併為 14 次。減少重複動畫取樣確實生效，但它不是目前整體行走成本的充分解法。

## 縮放診斷與畫面檢查

`movement-scale-diagnostic-20261008-fixed.json` 完成 53 項檢查與 12 段量測，零錯誤。低配、60 FPS、MSAA 關閉、相同道路與 16:10 視角下，交替測試 1280×800 輸出／0.9 倍縮放及 1152×720 輸出／1.0 倍，兩者的內部 3D 都是 1152×720。每種條件各三輪站立與轉鏡，所有區段的串流操作、動畫姿態與 seek 增量皆為零。

量測結束後另用實際按鍵取得 14 張畫面。已目視確認跑步姿態、離地／張臂衣襬姿態、回復站立，以及後續移動與操作恢復。截圖延遲可能超過一秒，檔名中的數字僅是請求時刻；它們不構成完整翻轉、每個落地階段或所有衣物穿插的視覺證明。這些畫面使用第一階段版本與 1152×720 輸出，動畫原始資料未變更。
