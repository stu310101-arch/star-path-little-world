# 手機 Web 下一階段優化

需求：iPhone 14／Safari 玩起來很卡，也要涵蓋較低階手機。以下是 2026-10-10 的程式與資源盤點，**不是 iPhone 真機效能驗收**。目前發布的是已驗證的桌機瀏覽器優化版；不能用桌機 Chrome 或瀏覽器手機視窗模擬，宣稱 Safari 已順暢。

## 已確認的負擔

候選版 `packs-60ebceee28b43f74` 首玩 PCK＋WASM 的選用壓縮 body 約 **104.94 MB**，加上按需室內內容約 **109.72 MB**，不含 HTML／JS／電腦小遊戲。

- 啟動 PCK：約 25.77 MB 傳輸、28.57 MB 解碼後檔案。
- WASM：約 10.11 MB 傳輸、39.51 MB 解碼後檔案；執行時記憶體還包含其他配置。
- 角色包：約 36.81 MB。兩個活動角色的匯入資源解壓後合計約 107.72 MB，還有休息模型、引擎物件及 GPU 資料。
- 字型來源約 11.94 MB，其匯入字型資源約 7.16 MB，屬啟動包的一部分。
- `world.gd` 開始漫遊前仍檢查全部 startup 包；所有室外區域與音樂都被列為 startup。
- 目前 `Web` 匯出 `vram_texture_compression/for_mobile=false`。需確認 Safari 的實際紋理格式支援與 fallback，不能僅憑設定斷定它就是卡頓原因。
- 區域細節節點已有卸載，但掛載的 PCK 仍保留在頁面生命週期中；卸掉場景節點不等於釋放整個資源包。

下載大小不等於峰值 RAM。啟動解壓／雜湊、WASM、MEMFS、已解碼角色與繪圖緩衝區可能同時存在。這次桌機角色合併提高走路頻率，但 Godot render-buffer 計數增加約 45 MiB；手機需要另做記憶體優先的驗證。

## 建議順序

| 優先 | 工作 | 預期作用與需要驗證的取捨 |
| --- | --- | --- |
| 1 | 首玩只等待起始區、角色及必要資源；遠區與各區音樂改成接近時預取 | 降低開場下載與同時持有的內容；保留世界與互動，驗證快速傳送、邊界移動、離線／重試。單做分區仍有約 76 MB 的啟動檔＋角色＋起始區負擔，不能宣稱立刻變成小遊戲。 |
| 2 | 角色把不變形零件和衣服分開，消除全身姿態中重複的零資料；再評估更緊密的衣服動畫表示 | 同時降低 CPU／GPU 工作與記憶體。保留骨骼、碰撞及動作時間；新表示必須重新做姿態、轉場及衣物畫面對照，不能直接刪掉衣服動態。 |
| 3 | 獨立手機 Web 匯出，提供手機支援的 VRAM 紋理格式；按畫面需要評估貼圖尺寸 | 避免把桌機紋理格式當成所有手機都支援。桌機與手機分別建包可避免所有人下載兩份格式；需真機確認材質、透明邊緣及色彩。降低尺寸可能影響近看清晰度，應另驗收。 |
| 4 | 字型依遊戲用字建立子集，動態輸入保留後備字型；精簡開場場景資源 | 降低啟動包及解析負擔；中文、標點、姓名與動態文字不能缺字。 |
| 5 | 降低手機啟動期間的下載並行、避免解壓後整檔多份副本；評估支援壓縮回應標頭的部署方式 | 壓低峰值 RAM。现有完整雜湊與失敗回退是必要契約，需重做中断／損壞測試；單純搬 CDN 不會修好走路 FPS。 |
| 6 | 手機專用可選畫質及幀率策略，在既有低配策略上量測 540–720p、30／60 FPS 與熱降頻 | 不更改物理、移速、相機操作規則；清晰度與流暢度的取捨應可選，不能以鎖 30 FPS 宣稱所有掉幀已解決。 |
| 7 | 自訂較小 Godot Web 匯出模板，關閉確定未使用的模組 | 降低引擎下載與初始化負擔；保留 3D、物理、中文文字處理、音訊及必要網路功能。更換模板會觸發目前的 loader SHA 防護，必須重新審查。 |
| 8 | 版本化離線快取／PWA | 改善第二次載入，並不解決第一次下載、執行時 RAM 或走路掉幀；需更新、容量及失敗回退策略。 |

## 驗收方式

首玩 **20–30 MB** 可作為後續目標，尚未達成；也不保證每個較低階型號都能維持 60 FPS。應明確選定最低支援機型，例如 iPhone SE 第二代／iPhone 11 與一台 4 GB Android 實機，依實測調整，而非僅以 iPhone 14 為標準。

每台實機分別測第一次載入、重開、站立／走路／跑跳、快速轉鏡頭、跨區、快速傳送、室內往返及連續遊玩 10–15 分鐘。記錄 Safari／Chrome console、是否網頁被重載、提交間隔分布、載入階段及記憶體訊號。手機觸控走路、轉視角、跳躍與互動亦需驗收；目前主要操作提示仍是鍵鼠。
