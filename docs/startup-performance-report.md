# 啟動下載與初始化實測（2026-10-01）

啟動必須下載的 PCK 已由 **154.56 MB 減至 35.40 MB（減少 77.09%）**，其他內容拆為延後包；首次全景也不再建立完整角色。最終版本機新瀏覽器 context 的首個畫面回呼由 **52.68 秒降至 43.02 秒**，同 context 再次開啟由 **48.40 秒降至 4.81 秒**。這是各一次的觀察；首次仍有很長的初始化阻塞，不能保證其他裝置固定達成這個速度，也不能稱為 PCK 已命中瀏覽器快取。

主要比較版本為 `streaming-3f7c73f0246b34c7` → `packs-c674b2a47ed31edd`，各自對應 `startup-before.json`、`startup-release.json`。前者是本輪修改前保留的匯出，不是更早的 176 MB 原版。中途 a1a1 版曾有較慢的首開及 Web 寫檔錯誤；失敗紀錄和修復後的獨立驗收均保留於下文，沒有把舊計時套用到新版本。精確 bytes、事件時間、雜湊與計數保存在 [startup-measurements.json](startup-measurements.json)；分包設計與可重現建置流程見 [startup-packs.md](startup-packs.md)。

**已實作的範圍**

1. 真正的網路分包：全景／碰撞／入口／UI 在啟動包；角色、區域、室內及音樂有獨立包，需驗證大小與 SHA-256 後才掛載。
2. 全景不建立完整角色；需要漫遊時才分開載入、建立及準備骨架。只準備當前需要的音樂，保留角色原始模型、動畫和形態鍵。
3. 在生成階段共用參數相同的材質與貼圖。Compatibility 的燈光編譯容量由 8／32 改為 4／8；實際室內 4 Omni＋1 Spot、全景 2 Directional 均保留，沒有改燈色、強度或解析度。容量及新增燈光的限制詳見架構文件。
4. 依實際執行期依賴閉包移除不需要發布的 entry，保留原資產；完全相同的 payload 可共用儲存。

依使用者指示，第五項版本化本機資源快取未實作。沒有新增 Service Worker、PWA 或 Cache Storage；既有畫面設定儲存不受影響。維持 Compatibility、單執行緒 Web、2× MSAA 預設與 30／60／90 FPS 選項。

**測試條件及指標定義**

- Windows 11、i7-1165G7、約 8 GB RAM；Chrome 154.0.8037.58 headless、1200×800、Intel Iris Xe／ANGLE D3D11。這不是使用者另一台電腦的數字。
- 同一 `tools/measure_startup_packs.cjs`，相同初始全景、MSAA 和幀率設定，以 localhost Python HTTP 伺服器提供檔案；不做網路／CPU 節流。本輪沒有測試新版本的 GitHub／Cloudflare 傳輸。
- 每版一個新 context，接著同 context 再次導航。未清除 OS／驅動層快取，也沒有足夠重複次數估計變異，因此「新 context」不等於所有硬體快取完全清空。
- `worldReady` 表示世界 `_ready()` 已完成；`firstRafAfterReady` 是之後第一個可執行的瀏覽器畫面回呼。後者可觀察主執行緒何時恢復，但不等於精確呈現時間或首個輸入延遲。
- 下載完成採 Resource Timing 中 PCK／WASM 的最後 `responseEnd`。進度條 MutationObserver 可能被主執行緒阻塞延後，不用其 `progressComplete` 冒充網路完成。
- WebGL API 包裝測量的是呼叫牆鐘時間，存在觀測成本；沒有取得獨立 GPU timer 或完整 CPU profiler。測試開始時間與原始記錄雜湊見 JSON。

同 context 再次開啟大幅變快，且大檔仍完整傳輸，**可推測**瀏覽器／驅動暖機影響了初始化；這不是已隔離證明的單一原因，也不是新增本機快取的效果。不能用這個 4.81 秒覆蓋首次仍需 43.02 秒的結果。

另保留中途驗證以避免只挑好的數字：分包與材質整理完成、尚未調整燈光容量的 `packs-8391b673f1753e4d`，兩次首個 rAF 為 **59.454／56.537 秒**。已改燈光容量、尚未修正 Web 寫檔流程的 `packs-a1a1d122a56b7fd4` 為 **66.035／6.341 秒**，該輪首開比基準慢。額外開啟 shader source 收集的診斷為 **93.259 秒**；包含請求攔截／故障注入的修復驗收也曾等到 **127.184 秒**才取得首個 rAF。後兩者不是同一個一般啟動探針設定，列為診斷／功能驗收，不混入主要速度比較。這些變動也說明不能只取最短結果保證所有首開都會改善。

最終版 `startup-release.json` 計時記錄有一筆未附 URL 的 console HTTP 404；已記錄的 PCK／WASM／角色包回應皆為 200。不能僅憑這份記錄判定 404 是哪個資源，也不將計時輪描述成零 console 錯誤。獨立的下載驗收與互動路線沒有非預期錯誤，兩類結果分開保留。

- 原生快速路線 29 項檢查通過，包含六區地面／玩家位置／互動、室內進出及返回同一世界，另有全景旋轉縮放、快速轉鏡及三次進出資料。
